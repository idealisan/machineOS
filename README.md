# Machine OS

一个从零开始编写的迷你操作系统内核。

## 目标平台

- 架构：X86 64 位
- 固件：传统 BIOS（非 UEFI）
- 引导：由 BIOS 加载并交接控制权，内核自行完成后续硬件初始化

## 定位

Machine OS 不基于任何现有操作系统进行改进，不继承 Linux、BSD 等系统的内核代码或
设计，是一个全新的操作系统内核实现。

## 设计取向

### 微内核

内核只保留最核心的机制：地址空间管理、线程与调度、进程间通信（IPC）、基本的中断
与异常处理。

所有驱动程序运行在用户态，以独立服务进程的形式存在，通过 IPC 与内核及其他服务通信。
驱动崩溃不会拖垮内核，可以单独重启，从而维护内核的稳定性。

### 放弃极限性能，换取可预测性

本系统不追求超高的吞吐与最低延迟，因此在设计上主动选择保守、易于分析的策略：

- **CPU 调度**：采用公平、保守的调度策略，行为可预测，优先保证响应时间的确定性，
  而非最大化利用率。
- **内存管理**：采用保守的内存管理策略，避免复杂的启发式回收与激进优化，使内存
  行为可推理、可观测。

这样的取舍换来的是更高的可预测性与实时性，适合作为研究与教学用的清晰内核。

## 路线图

1. BIOS 引导与内核早期初始化（实模式到长模式、串口与 VGA 文本输出）
2. 物理/虚拟内存管理、地址空间
3. 中断、异常与时钟
4. 线程与保守的公平调度器
5. 用户态进程与 IPC
6. 用户态驱动框架（键盘、磁盘、定时器等）
7. 文字控制台 shell 与基础工具集
8. 图形界面与更丰富的设备驱动

当前状态：一个可交互的最小闭环——内核在 1024×768×24 图形模式下显示深紫色桌面，
按 **A** 启动一个真正运行在 ring3 的 C 程序（它画出居中的红方块），
在该程序里按 **B** 通过 `exit` 系统调用退出，画面恢复为深紫色桌面。

用户程序通过 `syscall` 指令进入内核，走的是自定义系统调用号与寄存器约定，
这是后续所有用户态程序的基础。

## 启动流程

```
BIOS ──► stage 1（引导扇区，16 位）
           ├─ 设置段寄存器与栈
           └─ int 13h AH=42h 逐扇区读取 payload 到 0x7E00，跳转过去
             │
         stage 2（16 位 → 64 位，基址 0x7E00）
           ├─ 打开 A20，并做回绕校验
           ├─ 扫描 VBE 模式表，选中 1024x768x24 直接色 + 线性帧缓冲
           ├─ 加载 GDT（32 位代码/数据 + 64 位代码/数据）
           ├─ 进入 32 位保护模式
           ├─ 清零 BSS
           ├─ 建立页表：PML4 → PDPT → 4 个 PD，512x4 个 2M 页，恒等映射前 4 GiB
           │  （4 GiB 是因为 VBE 线性帧缓冲位于 0xFD000000 一带）
           ├─ 置 PAE、EFER.LME，开分页进入长模式
           ├─ 设置栈（16 KiB，16 字节对齐，满足 System V AMD64 ABI）
           └─ call kernel_main()
```

中断在进入保护模式时即关闭（`cli`），在建立 IDT 之前不会再打开，
避免空 IDT 收到时钟中断直接触发三重故障。

之后内核进入"桌面"循环：

```
kernel_main
   ├─ 填满深紫色背景
   ├─ 轮询 PS/2 键盘（端口 0x60/0x64）
   └─ 读到 A（扫描码 0x1E）
        ├─ 把用户程序从内核镜像复制到 0x200000
        ├─ 写好 boot_info（帧缓冲地址、行间距、红色像素值）
        ├─ iretq 进入 ring3（CS=0x33, SS=0x2B, RSP=0x3FF000）
        ├─ 用户程序画 256x192 红方块，循环 syscall 读键盘
        └─ 读到 B（扫描码 0x30）→ exit 系统调用 → 回到桌面并重绘紫色
```

## 内存管理

物理内存用**位图**管理，一帧 4 KiB，一位代表一帧（0 = 空闲，1 = 占用）。极简：

- 不支持超额分配，不支持交换，不做页面回收；
- 只提供 `pmm_alloc()` / `pmm_free()`，另有统计函数；
- 分配不保证连续，返回的是物理地址，不涉及页表映射。

内存地图来自 BIOS E820：stage 2 在实模式下逐条读取并复制到 `e820_entries`，
内核启动时据此把所有"可用"区间在位图里放开，然后把这些区域标记为保留：

- `0 .. kernel_end`（内核镜像，含位图自身）；
- `0x200000 .. 0x400000`（用户程序与它的栈所在的 2 MiB 页）。

位图固定支持到 4 GiB 物理内存（1 M 帧 = 128 KiB 位图），超出部分直接忽略。
由于位图在 `.bss` 里，链接脚本加了 `ASSERT(kernel_end <= 0x200000)`，
保证内核不会长到用户页上去。

分配时带一个游标，从上次分配位置继续向后找，找不到再回绕到低位，
避免每次都从 0 开始扫描。释放会把游标退回到更小的帧号，便于复用。

启动时串口会打印一行自检结果，例如 256 MiB 的 QEMU 上：

```
pmm: total=65407 free=64838
pmm: alloc 0x0000000000039000
pmm: alloc 0x000000000003a000
pmm: alloc 0x000000000003b000
pmm: free after release=64838 (ok)
pmm: reject unaligned=ok double-free=ok
```

## 用户态与系统调用

本阶段是**协作式**的：没有调度器、没有内存管理、没有中断处理。内核只在
`enter_user()` 里等待一个用户程序返回，用户程序自己轮询键盘。

### 系统调用 ABI

| 项 | 约定 |
| --- | --- |
| 触发 | `syscall` 指令（`EFER.SCE`、`STAR`、`LSTAR`、`FMASK` 由内核设置） |
| 编号 | `rax` |
| 参数 | `rdi, rsi, rdx`（最多三个） |
| 返回 | `rax`，出错返回负值 |
| 内核保证不改的寄存器 | 除 `rax`、`rcx`、`r11` 外的全部通用寄存器 |
| 编号分配 | `0 exit(status)`、`1 write(fd, buf, len)`、`2 read_key()` |

`write` 目前只写串口（`-serial`），`read_key` 返回 PS/2 扫描码、无按键返回 -1。
`STAR` 让 `sysret` 回到 `CS=0x33 / SS=0x2B`；进入内核时 `FMASK` 会清掉
`IF/TF/DF/NT/AC/IOPL`。

### 本阶段的刻意简化

- 用户程序固定加载在 **0x200000**，栈顶 **0x3FF000**，都落在 stage 2 标记为
  User 可访问的那一个 2 MiB 页里；暂时没有 ELF 装载器。
- 帧缓冲所在的 2 MiB 页也对用户开放，所以程序可以直接画像素。
  这是为了先跑通系统调用链路，后续会把绘制改成系统调用。
- 没有 IDT：用户态一旦触发异常，会直接三重故障重启。
- 键盘靠轮询，中断全部屏蔽。
- 地址空间只有一套，用户页与内核页靠 2 MiB 页的 U/S 位隔离。

## 构建与运行

依赖：NASM、clang（需支持 `-target x86_64-elf`）、ld.lld、QEMU。
见 `docs/0001-development-environment-report.md`；`ld.lld` 可用 `brew install lld` 安装。

```
./scripts/run.sh    # 推荐：一条命令完成构建 + 启动 + 弹出虚拟屏幕
make                # 仅构建 build/machine-os.img
make run            # 构建并启动
```

`scripts/run.sh` 会检查依赖、做增量构建，然后用 QEMU 打开窗口显示虚拟屏幕，
便于开发者和测试人员直接观察引导效果。额外参数会原样传给 QEMU，例如：

```
./scripts/run.sh -display none      # 无窗口运行
./scripts/run.sh -s -S              # 等待调试器连接
```

窗口内快捷键：`Ctrl+Alt+2` 进入 QEMU 监视器，`Ctrl+Alt+1` 返回，关闭窗口即退出。

启动后在窗口里按 **A** 启动用户程序，按 **B** 退出；无窗口模式下可以用
QEMU 监视器发按键：`sendkey a` / `sendkey b`。

镜像 = 512 字节引导扇区 + payload（扇区数由构建时自动计算并写进引导扇区）。

启动后屏幕切换为 1024×768×24 位色，C 内核按 VBE 模式信息块里的帧缓冲地址、
行间距和各通道位偏移计算颜色值，填满整屏深紫色背景，然后停在 `hlt` 循环。

如果机器（或模拟器）没有提供 1024×768×24 的线性帧缓冲模式，stage 2 会保持文本模式，
内核退回文本提示而不是黑屏。

## 编译器与 ABI

当前阶段的选择：

- **编译器**：clang，目标三元组 `x86_64-elf`，freestanding（无 libc、无运行时），
  关闭 red zone、SSE 与 x87，避免在内核尚未初始化 FPU 时踩到意外状态。
- **C 调用约定**：暂时采用 **System V AMD64 ABI**，与 Linux 上的 C 编译器一致，
  这样现有 C 代码与编译器后端可以直接使用。
- **系统调用接口**：不沿用 Linux，将来由本内核自行定义（寄存器约定、调用号、
  返回语义），属于独立设计，不随用户态 C ABI 变化。

长期看，如果自定义的调用约定或对象格式无法用现有目标三元组表达，再考虑自建
工具链（自有 Clang target description / 自定义链接器）；现阶段不为尚未确定的
需求提前付出成本。
