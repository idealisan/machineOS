# Machine OS

一个从零开始编写的迷你操作系统内核。

## 目标平台

- 架构：X86 64 位
- 固件：传统 BIOS（非 UEFI）
- 引导：由 BIOS 加载并交接控制权，内核自行完成后续硬件初始化

## 定位

Machine OS 不基于任何现有操作系统进行改进，不继承 Linux、BSD 等系统的内核代码或
设计，是一个全新的操作系统内核实现。

## 设计取向

### 微内核

内核只保留最核心的机制：地址空间管理、线程与调度、进程间通信（IPC）、基本的中断
与异常处理。

所有驱动程序运行在用户态，以独立服务进程的形式存在，通过 IPC 与内核及其他服务通信。
驱动崩溃不会拖垮内核，可以单独重启，从而维护内核的稳定性。

### 放弃极限性能，换取可预测性

本系统不追求超高的吞吐与最低延迟，因此在设计上主动选择保守、易于分析的策略：

- **CPU 调度**：采用公平、保守的调度策略，行为可预测，优先保证响应时间的确定性，
  而非最大化利用率。
- **内存管理**：采用保守的内存管理策略，避免复杂的启发式回收与激进优化，使内存
  行为可推理、可观测。

这样的取舍换来的是更高的可预测性与实时性，适合作为研究与教学用的清晰内核。

## 路线图

1. BIOS 引导与内核早期初始化（实模式到长模式、串口与 VGA 文本输出）
2. 物理/虚拟内存管理、地址空间
3. 中断、异常与时钟
4. 线程与保守的公平调度器
5. 用户态进程与 IPC
6. 用户态驱动框架（键盘、磁盘、定时器等）
7. 文字控制台 shell 与基础工具集
8. 图形界面与更丰富的设备驱动

当前状态：在 64 位长模式下运行 C 内核，并已通过 VBE 切换到 1024×768×24 真彩色图形模式，
全屏渲染深紫色（#300050）背景。

## 启动流程

```
BIOS ──► stage 1（引导扇区，16 位）
           ├─ 设置段寄存器与栈
           └─ int 13h AH=42h 逐扇区读取 payload 到 0x7E00，跳转过去
             │
         stage 2（16 位 → 64 位，基址 0x7E00）
           ├─ 打开 A20，并做回绕校验
           ├─ 扫描 VBE 模式表，选中 1024x768x24 直接色 + 线性帧缓冲
           ├─ 加载 GDT（32 位代码/数据 + 64 位代码/数据）
           ├─ 进入 32 位保护模式
           ├─ 清零 BSS
           ├─ 建立页表：PML4 → PDPT → 4 个 PD，512x4 个 2M 页，恒等映射前 4 GiB
           │  （4 GiB 是因为 VBE 线性帧缓冲位于 0xFD000000 一带）
           ├─ 置 PAE、EFER.LME，开分页进入长模式
           ├─ 设置栈（16 KiB，16 字节对齐，满足 System V AMD64 ABI）
           └─ call kernel_main()
```

中断在进入保护模式时即关闭（`cli`），在建立 IDT 之前不会再打开，
避免空 IDT 收到时钟中断直接触发三重故障。

## 构建与运行

依赖：NASM、clang（需支持 `-target x86_64-elf`）、ld.lld、QEMU。
见 `docs/0001-development-environment-report.md`；`ld.lld` 可用 `brew install lld` 安装。

```
./scripts/run.sh    # 推荐：一条命令完成构建 + 启动 + 弹出虚拟屏幕
make                # 仅构建 build/machine-os.img
make run            # 构建并启动
```

`scripts/run.sh` 会检查依赖、做增量构建，然后用 QEMU 打开窗口显示虚拟屏幕，
便于开发者和测试人员直接观察引导效果。额外参数会原样传给 QEMU，例如：

```
./scripts/run.sh -display none      # 无窗口运行
./scripts/run.sh -s -S              # 等待调试器连接
```

窗口内快捷键：`Ctrl+Alt+2` 进入 QEMU 监视器，`Ctrl+Alt+1` 返回，关闭窗口即退出。

镜像 = 512 字节引导扇区 + payload（扇区数由构建时自动计算并写进引导扇区）。

启动后屏幕切换为 1024×768×24 位色，C 内核按 VBE 模式信息块里的帧缓冲地址、
行间距和各通道位偏移计算颜色值，填满整屏深紫色背景，然后停在 `hlt` 循环。

如果机器（或模拟器）没有提供 1024×768×24 的线性帧缓冲模式，stage 2 会保持文本模式，
内核退回文本提示而不是黑屏。

## 编译器与 ABI

当前阶段的选择：

- **编译器**：clang，目标三元组 `x86_64-elf`，freestanding（无 libc、无运行时），
  关闭 red zone、SSE 与 x87，避免在内核尚未初始化 FPU 时踩到意外状态。
- **C 调用约定**：暂时采用 **System V AMD64 ABI**，与 Linux 上的 C 编译器一致，
  这样现有 C 代码与编译器后端可以直接使用。
- **系统调用接口**：不沿用 Linux，将来由本内核自行定义（寄存器约定、调用号、
  返回语义），属于独立设计，不随用户态 C ABI 变化。

长期看，如果自定义的调用约定或对象格式无法用现有目标三元组表达，再考虑自建
工具链（自有 Clang target description / 自定义链接器）；现阶段不为尚未确定的
需求提前付出成本。
