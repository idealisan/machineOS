# Machine OS

一个从零开始编写的迷你操作系统内核。

## 目标平台

- 架构：X86 64 位
- 固件：传统 BIOS（非 UEFI）
- 引导：由 BIOS 加载并交接控制权，内核自行完成后续硬件初始化

## 定位

Machine OS 不基于任何现有操作系统进行改进，不继承 Linux、BSD 等系统的内核代码或
设计，是一个全新的操作系统内核实现。

## 设计取向

### 微内核

内核只保留最核心的机制：地址空间管理、线程与调度、进程间通信（IPC）、基本的中断
与异常处理。

所有驱动程序运行在用户态，以独立服务进程的形式存在，通过 IPC 与内核及其他服务通信。
驱动崩溃不会拖垮内核，可以单独重启，从而维护内核的稳定性。

### 放弃极限性能，换取可预测性

本系统不追求超高的吞吐与最低延迟，因此在设计上主动选择保守、易于分析的策略：

- **CPU 调度**：采用公平、保守的调度策略，行为可预测，优先保证响应时间的确定性，
  而非最大化利用率。
- **内存管理**：采用保守的内存管理策略，避免复杂的启发式回收与激进优化，使内存
  行为可推理、可观测。

这样的取舍换来的是更高的可预测性与实时性，适合作为研究与教学用的清晰内核。

## 路线图

1. BIOS 引导与内核早期初始化（实模式到长模式、串口与 VGA 文本输出）
2. 物理/虚拟内存管理、地址空间
3. 中断、异常与时钟
4. 线程与保守的公平调度器
5. 用户态进程与 IPC
6. 用户态驱动框架（键盘、磁盘、定时器等）
7. 文字控制台 shell 与基础工具集
8. 图形界面与更丰富的设备驱动

当前状态：阶段 1 完成——引导扇区能由 BIOS 加载、建立段与栈、输出启动标识并停机。

## 构建与运行

依赖：NASM、QEMU（见 `docs/0001-development-environment-report.md`）。

```
make        # 生成 build/machine-os.img（当前为 512 字节引导扇区）
make run    # 在 QEMU 中启动
```

当前镜像只含引导扇区：BIOS 加载后屏幕显示两行启动标识，随后 `hlt` 停机。

## 待决策：编译器与 ABI

Machine OS 不沿用 Linux 的二进制接口，因此 C 语言层面的 ABI 需要自行定义：

- 系统调用约定（哪些寄存器传参、如何编号）由本内核规定，与 Linux 无关；
- 用户态与内核态的调用约定需要和编译器配合，理想情况是一套自有 GCC/Clang
  后端描述文件（spec/target description），而非迁就现有目标平台；
- 因此在引入 C 语言之前，先完成启动路径与最小运行时，再评估"直接使用
  `x86_64-elf` 目标 + 自定义调用约定"是否足够，或是否需要自建工具链。

该问题在阶段 1 之后再讨论，当前所有代码均为汇编。
